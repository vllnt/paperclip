# Black and white theme (Vercel-style, no grey)

Status: implemented on branch `feat/bw-theme`, awaiting review. Owner: UI track. Requested 2026-10-09.

## Goal

- Dark: surfaces pure `#000`, primary text `#fff`.
- Light: surfaces pure `#fff`, primary text `#000`.
- No grey-tinted backgrounds, cards, sidebars or panels.
- Hierarchy comes from the foreground colour at reduced strength, and from a 1 px border for elevation. Never from a grey hex or a grey fill.
- Error, warning, success and link/focus keep clear accent colours, used sparingly. Text keeps WCAG AA contrast.
- Mode switch: System (default), Light, Dark. Persisted; no flash of the wrong theme on load.

## What existed before

The token layer is `ui/src/index.css` (Tailwind v4, shadcn-style OKLCH variables, `.dark` class, `@theme inline` maps them to utilities). `ThemeContext` toggled light/dark and a boot script in `ui/index.html` applied the stored choice before first paint. All neutrals were chroma-0 greys: dark background `oklch(0.205)`, light `muted`/`accent`/`secondary` at `0.97`, borders at `0.922`.

## Tokens

Only a few primitives differ per mode. Everything else is derived in one shared `:root, .dark` block, so it re-resolves inside a nested `.dark` container too.

## How hierarchy works without grey

- Text: `foreground` for primary, `--muted-foreground` (foreground at 64%) for secondary. A third level, if needed, is `text-muted-foreground/NN`, but anything below about 56% fails AA for body text.
- Dividers and card edges: `--border` (foreground at 10% / 14%). A card is `--background` plus a 1 px border; it is not a lighter or darker fill.
- Hover and selected: `--accent`, which is foreground at 6% / 10% over the background. Strong selection: the inverted pill (`bg-primary text-primary-foreground`).
- Form controls: transparent fill plus an `--input` border, strong enough to meet 3:1. The old `dark:bg-input/30` fills are removed from `Input`, `Textarea`, `Select` and `Checkbox`. The outline `Button` uses `border-input` in both modes and `hover:bg-accent` for hover.
- Docks and bars: the mobile bottom navigation is `bg-background` with a top `border-border`, not a tinted bar.
- Fills are opaque `color-mix(fg N%, bg)` rather than literal alpha. Over a pure surface they render the same as an overlay, but sticky headers and the sidebar "action cover" (`.primary-sidebar-surface`) need an opaque colour so content does not show through. Borders and text are true alpha because they must sit on top of coloured chips.
- Status: neutral statuses (backlog, cancelled, idle) use `--status-neutral`. Active statuses keep their accent hues.

## Mode switch and persistence

- Preference values: `system` (default), `light`, `dark`. Stored in `localStorage["paperclip.theme"]`. `system` removes the key so existing `light` / `dark` values keep working.
- `ui/index.html` boot script resolves the preference before first paint (class `dark`, `color-scheme`, `<meta name="theme-color">` = `#000` / `#fff`). Reading storage and reading the OS preference are guarded separately, so blocked or unreadable storage still follows the OS (light when the OS reports nothing), exactly as `ThemeContext` resolves an unset preference. `ui/src/boot-theme-script.test.ts` runs the real script against every storage and OS combination.
- `ThemeContext` exposes `preference`, `theme` (resolved) and `setPreference`. It follows OS changes while the preference is `system`, and syncs across tabs through the `storage` event.
- UI: a three-option control in the account menu and on the signed-out `/auth` page.
- Not in scope: syncing the preference across devices per user. That needs a DB column, an API and shared types.

## Exceptions (colours that stay as they are)

- Agent capsule gradients (`--agent-*`, `--agent-cap-v1-*`) and the onboarding mascot (`--pill-guy-*`): brand artwork.
- User-chosen colours: project and folder colours (`--folder-color-*`, `--project-seed`), label colours.
- Syntax highlighting hues inside code blocks. The code-block surface itself uses tokens.
- xterm.js terminal theme (`CompanyEnvironments.tsx`): a third-party option object.
- Server-rendered exports such as the org chart SVG: static files that cannot read CSS variables.
- Uploaded images and screenshots.
- Loading skeletons (`Skeleton`, `bg-accent/75`): a placeholder needs a quiet fill to be visible. The e2e grey-panel scan skips `data-slot="skeleton"`.
- Scrims and media overlays (`bg-black/50` on dialogs and sheets, the image gallery, attachment hover overlays, `text-white/NN` on those overlays). They sit on top of images or dim the page and stay dark in both modes.
- Text colour chosen over a user-picked pill colour (`READABLE_TEXT_LIGHT` / `READABLE_TEXT_DARK`, now pure white and pure black) and the worktree badge text pair in `server/src/ui-branding.ts`.
- The "no project" pill fallback in `IssueColumns.tsx` (`grey-gate: allow`): it feeds contrast maths that needs a real hex.
- Semantic accents (red, amber, green, blue, violet) used for status, error and links. The blue human-message bubbles in task chat keep their existing accent.

## Guard

`scripts/check-token-gates.mjs` gets a grey gate: it fails on Tailwind `gray/zinc/neutral/slate/stone` palette classes and on grey hex/`rgb()`/`oklch(L 0 0)` literals in `ui/src/components/**` and `ui/src/pages/**`, outside the existing allowlist. A vitest contract test checks that the light and dark token values are pure and meet the contrast numbers above.
